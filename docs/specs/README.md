# Specs

Written specifications produced by the `brainstorming` skill, one file per piece of work.
A spec captures the agreed problem, scope, and constraints **before** a plan is written
and before any code is written.

Naming: `NNN-short-slug.md`, matching the corresponding plan in `docs/plans/`.

A spec should state what problem is being solved, what is explicitly out of scope, and
what "done" looks like in observable terms.
